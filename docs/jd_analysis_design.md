# 근거 중심 JD 분석 1차 설계

## 목적

사용자가 선택한 채용공고 PDF에서 요구사항을 추출하고, `내 프로필`에 저장된 경험 및 추적 기업의 공식 동향과 근거별로 연결한다. 현재 세부 역량 사전은 반도체 직무를 우선 지원하며, 다른 산업은 외부 회사 조사 모드로 구분한다. 합격 가능성이나 지원자 간 우열은 판단하지 않는다.

## 결과 구분

1. **원문 사실**: JD에 실제 존재하는 문장, 필수·우대·담당 업무 표시, 원문 포함 여부
2. **자동 해석**: JD와 경험에 함께 나타나는 표준 역량 분류. 두 원문을 항상 나란히 표시한다.
3. **회사 공식 동향**: 추적 기업의 공식 기사 중 JD 직무·기술 분류와 겹치는 자료. 필수 역량 판단에는 사용하지 않는다.
4. **자동 제안**: JD·공식 동향·입력 경험의 연결을 바탕으로 한 이력서 및 학습 방향. 사실과 별도 라벨로 표시한다.

## 출처 등급

- A: 사용자가 기업 공식 채용공고라고 확인한 원문
- B: 채용 플랫폼 또는 채용 대행사에 게시된 원문
- C: 출처를 확인하지 못한 복사본

등급은 사용자가 선택한 출처 유형이며, 시스템이 주소의 진위를 자동 보증하지 않는다. 화면에는 확인일과 공고 주소를 함께 표시한다.

## 표준 역량 분류

웨이퍼 핵심 공정, 공정 안정화·조건 최적화·수율, 장비 Set-up·개조·협력사 협업, AMHS·반송 제어, 파생제품·요소기술, 공정 흐름·원리, 공정 실험, TEST·분석 프로그램, 관련 전공을 1차 반도체 목록으로 사용한다. 분류 목록과 근거 규칙은 `docs/jd-analyzer-v4.js`에서 관리한다. (26회차 정정: 구버전 v2를 가리키던 낡은 문장. 실제 화면은 v4만 쓴다 — `docs/index.html:13`.)

## 예외 처리

- 필수·우대 표기가 없으면 `구분 없음`으로 유지한다.
- 여러 직무가 섞였을 가능성이 있으면 지원 직무 부분만 남기라는 경고를 표시한다.
- JD가 짧으면 제한적 분석임을 표시한다.
- 경험이 없으면 연결 근거 없음으로 표시하되, 사용자의 실제 역량이 없다고 단정하지 않는다.
- 원문에서 다시 찾을 수 없는 인용은 검증 실패로 표시한다.
- 줄바꿈이 사라진 PDF·복사문은 영문 섹션 제목, 한국어 안내 문구와 글머리표를 이용해 다시 나눈다.
- 프로필이 없어도 JD 요구사항, 반복 역량, JD 기반 공부 주제는 정상적으로 제공한다.
- 프로필이 있을 때만 경험 매칭과 프로필 대비 보완 제안을 추가한다.

## JD 기반 추천 문항

- 요구사항에서 반복되는 표준 역량을 기준으로 최대 4개의 자소서 연습 문항을 제안한다.
- 각 문항에는 생성 근거가 된 JD 문장 번호를 표시한다.
- 프로필에서 연결할 경험이 있으면 경험 번호와 원문을 표시하고, 없으면 근거가 없다고 알린다.
- 이 결과는 실제 기업이 공개한 자소서 문항이 아니라 `JD 기반 추천`으로 명확히 표시한다.
- 실제 기업 문항 분석은 사용자가 해당 문항을 직접 입력한 경우에만 별도 기능으로 제공한다.

## 2차 결과 화면 원칙

- 분석 전 `PDF 추출 원본 → 정리 미리보기 → 사용자 확인·수정 → 분석` 순서를 반드시 거친다.
- 쉼표나 마침표 개수가 아니라 소제목, 글머리표, 이어지는 줄을 이용해 의미 단위를 만든다.
- 결과 첫 화면에는 한 줄 해석, 업무 블록, 이력서 강조 역량 Top 5, 공고 특징, 도메인 공부 주제를 순서대로 표시한다.
- JD 원문 전체와 분류 사유는 접기 영역에 두고, 결론 카드의 근거 번호로 연결한다.
- `사실`은 JD 인용·의미 단위 집계에만 붙이고, 중요성·작성 방향·학습 주제는 `해석` 또는 `제안`으로 구분한다.
- 한 JD 안에서 많이 등장한 횟수를 중요도 점수로 사용하지 않는다. Top 5는 서로 다른 업무 의미 단위에서 하나씩 선택한다.
- 프로필 비교는 독립 결과표로 만들지 않는다. 각 이력서 전략 카드 안에서 연결되는 사용자 활동과 작성 방향을 함께 보여준다.

## 이미지형 PDF

- 내장 글자가 거의 없는 PDF는 PDF.js로 각 페이지를 이미지로 만든 뒤 Tesseract.js의 한국어·영어 OCR을 브라우저에서 실행한다.
- OCR은 처리 시간을 고려해 10쪽 이하로 제한하며 파일 자체는 서버에 업로드하지 않는다.
- OCR 결과는 바로 분석하지 않고 오타 의심 경고와 정리 미리보기를 먼저 보여준다.

## 개인정보와 비용

현재 버전은 브라우저 안에서만 작동한다. PDF와 JD 원문은 서버로 전송하지 않으며 API 비용도 발생하지 않는다. 내 프로필은 현재 브라우저의 저장 공간에만 보관하며 공개 웹페이지나 GitHub에는 저장하지 않는다. 공개 웹페이지의 자바스크립트에는 AI API 키를 넣지 않는다.

PDF 입력은 Mozilla PDF.js를 이용해 브라우저 안에서 처리한다. PDF 파일 자체는 서버로 전송하지 않는다. 내장 글자가 거의 없는 이미지 스캔본은 10쪽까지 Tesseract.js 한글·영문 OCR을 실행한다. 파일 크기는 20MB, 내장 글자 PDF는 150쪽으로 제한한다. 원문 입력칸은 기본 화면에서 숨기고 `추출 원문 확인·수정` 안에서만 제공한다.

## 프로필과 회사별 직무명

- 경험은 JD마다 반복 입력하지 않고 `내 프로필`에 한 번 저장한다.
- 프로필은 JSON 백업 파일로 내보내고 다시 불러올 수 있다.
- PDF에서 회사와 직무 후보를 찾되 사용자가 최종 확인한다.
- 여러 직무가 발견되면 분석할 직무를 사용자가 선택한다.
- 회사의 실제 직무명은 그대로 보존한다.
- 삼성전자 `공정기술`, SK hynix `양산기술`처럼 명칭이 달라도 비교를 위해 `공정·양산 엔지니어링` 같은 공통 분류를 함께 표시한다.
- 공통 분류는 자동 해석임을 표시하고 실제 JD 원문보다 우선하지 않는다.

## 구조화 프로필

- SK하이닉스 지원서 입력 가이드를 참고해 학교별 학력, 전공 과목·성적, 대학원 연구·논문·학회, 기술·자격·어학을 분리해 저장한다.
- 경험은 유형·기간·기관·역할·문제·행동·결과·도구로 구분해 저장하고 JD 및 자소서 문항 연결에 사용한다.
- AI 기반 문제해결 경험은 문제 상황·역할·AI 활용·검증·결과를 분리하며 단순 질의응답을 경험으로 포장하지 않는다.
- 이전 단일 텍스트 프로필은 새 형식으로 자동 변환한다.

## 회사 동향 결합

- 추적 기업 11개는 저장된 공식 기사 중 직무 분류, 기술 분야, 공정 연결 등급이 JD와 겹치는 자료만 최대 3건 표시한다.
- 회사 기사는 `N` 근거 번호를 사용하며 JD 요구사항 `J`와 섞지 않는다.
- 기사 건수는 공식 발표 빈도일 뿐 채용 중요도나 시장점유율로 해석하지 않는다.
- 직접 연결할 공식 기사가 없으면 일반 뉴스를 억지로 붙이지 않는다.
- 추적하지 않는 회사는 외부 회사 조사 모드로 표시하고, 공식 채용·뉴스룸·IR 자료와 확인일이 확보되기 전까지 회사 동향을 생성하지 않는다.

## 검증 계획

1. 사람이 직접 필수·우대·담당 업무를 표시한 다양한 직무 JD 표본을 만든다.
2. 요구사항 추출 정확률과 누락률을 계산한다.
3. 표준 역량 분류가 너무 넓게 연결된 사례와 놓친 사례를 기록한다.
4. 규칙을 수정한 전후 결과를 같은 표본으로 비교한다.
5. 추출·인용 검증이 안정된 뒤에만 보안이 확보된 AI 분석을 연결한다.

현재 자동 테스트는 원문 인용 확인, 필수·우대 구분, 경험 매칭, JD에 없는 SPC·DOE의 임의 생성 방지, 구분 없는 JD와 복수 직무 경고를 검사한다.
